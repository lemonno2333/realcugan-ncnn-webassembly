# 动画性能优化记录

## 目标与边界

在不重新设计界面、不移除主要视觉层级的前提下，优先降低页面常驻动画带来的 GPU 合成、滤镜重绘和 JavaScript 每帧执行成本。`web-re` 的动画结构与视觉语义继续保留，优化以 CSS 原生能力和静态降级为主，不引入依赖。

## 成本判断

### 第一优先：持续渲染成本

1. `.ambient-proc`
   - 固定全屏、超出视口、`blur(70px) saturate(...)`，且三个大色块持续变换。
   - 这是处理期间最重的大面积滤镜层。
2. `.mesh` 与 `.mesh span`
   - 四个模糊色块持续变换，父层同时改变背景位置和变换。
   - `filter: url(#rc-liquid)` 使用 `feTurbulence` 与 `feDisplacementMap`，和运动叠加时成本很高。
3. `.grain-svg`
   - 固定全屏 SVG 噪点叠加混合模式，并以较高频率持续位移。
4. 自定义光标与空状态圆环
   - 两套 `requestAnimationFrame` 在页面存续期间持续运行，即使画面已经静止。

### 第二优先：设备相关成本

- 移动端更容易受到全屏固定背景、滤镜和混合模式影响，应将装饰层静态化或隐藏。
- `prefers-reduced-motion` 下应停止循环背景和自定义光标，而不是只把动画时长压到接近零。
- `background-attachment: fixed` 在可滚动的小屏页面上更容易触发背景重绘；桌面一屏布局下优先级较低。

### 第三优先：交互瞬时成本

- `left`、`width`、`height`、`max-width` 和 `box-shadow` 动画会触发布局或绘制，但这里只在参数切换、悬停或处理进度变化时发生，不属于主要常驻成本。
- `@property --c-*` 的颜色过渡只在主题或图片取色变化时发生，不是长期烧帧来源；可缩短持续时间，但优先级低于全屏滤镜层。

## 代码核对后的修正

- 当前 DOM 中存在 3 个 `[data-parallax]` 装饰文字，因此 `pointermove` 中的查询不是空查。优化方式应是初始化时缓存节点，而不是删除视差效果。
- `.mesh` 的 SVG 液化滤镜不仅出现在揭示关键帧中，也由 `.liquid` 在整个处理阶段持续应用；只改关键帧不能消除主要成本。
- 空状态圆环已有等价 CSS `spin` 动画，额外的 JavaScript RAF 仅用于悬停加速，可由 CSS 动画时长完成。

## 本轮实施

1. 降低全屏环境光和网格色块的模糊半径，保留颜色、运动轨迹和节奏。
2. 移除 `.mesh` 的 SVG 位移滤镜，保留渐变、模糊、混合、漂移和揭示淡出。
3. 降低全屏颗粒动画刷新频率，保留颗粒质感。
4. 用 CSS 动画替代空状态圆环的常驻 JavaScript RAF。
5. 自定义光标改为按需 RAF：指针移动时启动，追上目标后停止；视差节点只查询一次。
6. 移动端隐藏环境光与颗粒，网格保留静态视觉；关闭固定背景。
7. `prefers-reduced-motion` 下跳过自定义光标初始化，并明确隐藏高成本装饰层。
8. 缩短动态主题色过渡，降低切换期间的长时间重绘。

## 暂不改动

- 暂不把倍率条、降噪刻度和所有进度条重写为 `transform`，避免为低频交互扩大模板和状态计算改动。
- 暂不删除装饰文字视差、自定义光标、处理网格或主题取色过渡。
- 暂不重做 `body::before` / `body::after` 的双层交叉淡入结构；当前收益不足以抵消改造范围。

如后续仍有可测量的掉帧，再用浏览器 Performance / Rendering 面板针对具体设备采样，决定是否进入更激进的静态背景或预渲染方案。
